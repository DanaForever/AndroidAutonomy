01 · How it works

AutoDevice at a glance

AutoDevice is an autonomous Android agent for app testing. It reached 2nd place on AndroidWorld across 20+ real apps. It splits the work into two roles, and it picks a different model for each.

◇ Planner

Strategy

"Find the save button."

Breaks the task into goals. Issues high-level, semantic instructions. Does not tap the screen itself.

◆ Executor

Pixel actions

Justify the action from what is on screen.

Turns each goal into a precise pixel tap. Must ground the action in the live screen, so it cannot invent clicks.

AutoDevice does not use one model. A router sends each step to a model that fits its difficulty.

easy and medium go to Sonnet. hard steps go to Gemini 3 Pro. the executor is always Haiku. all use prompt caching.

02 · The supporting parts

What holds the score up

Three systems do the heavy lifting behind the planner and executor.

perception

Screen Transcription

A dedicated agent reads the text on screen, like OCR, at 93%+ accuracy. It runs before any action, so the executor knows what is really there.

recovery

Narrative Feedback

When a step fails, it returns a plain-language summary of what happened, not an error code. The planner reads it and can switch to a new approach.

memory

Scratchpad

A key-value store that survives app restarts and long contexts. It lets the agent carry data across apps during multi-step tasks.

A few field notes they call out from real runs.

+30% speed

Search, do not scroll

Agents are about 30% faster when they look for a Filter or Search icon instead of scrolling.

reliability

Verify after typing

Android text input is unreliable. Always re-read the field after typing.

cost

Prompt caching

Caching cut cost and latency on long multi-step tasks.
